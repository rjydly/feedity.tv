===============================================================================
FEEDITY VIDEO PIPELINE — ESPECIFICACIÓ TÈCNICA I ARQUITECTURA DEL SISTEMA
===============================================================================
Fitxer de referència tècnica per a desenvolupadors i models d'IA.
Data de revisió: 2026
Objectiu: Normalització, comprensió visual, redisseny i composició automàtica
de vídeos curts (Instagram Reels / TikTok) en format vertical 9:16 (1080x1920 px).

-------------------------------------------------------------------------------
1. VISIÓ GENERAL DEL PIPELINE I FLUX DE DADES
-------------------------------------------------------------------------------

El sistema combina una capa serverless d'ingesta ràpida (Telegram + Cloudflare)
amb un motor d'edició i renderitzat per lots a GitHub Actions:

1. Ingesta Immediata [Telegram -> Cloudflare Worker -> GitHub API]:
   L'usuari comparteix un Reel directament al Bot de Telegram. Un Cloudflare Worker
   serverless valida l'enllaç, comprova el Chat ID autoritzat i afegeix la fila
   'url,pending' directament a [sources.csv] mitjançant l'API REST de GitHub.
2. Cua d'Execució [GitHub Actions / Cron]:
   El pipeline llegeix [sources.csv] i selecciona el primer element amb estat 'pending'.
3. Descàrrega de Vídeo [yt-dlp]:
   Descàrrega en format MP4 (amb suport de cookies.txt i gestió de VFR).
4. Visió per Computador [OpenCV + NumPy]:
   Detecció del requadre del vídeo real mitjançant anàlisi de seqüència contínua
   (Run-Length Spatial Span) ignorant fons negres/blancs i text estàtic.
5. Intel·ligència Artificial [Gemini 3.6 Flash -> Groq Fallback]:
   Comprensió de l'escena, OCR del text original, identificació de l'autor primari,
   paràfrasi viral en anglès amb negretes (**bold**) i redacció del caption complet.
6. Motor Tipogràfic [Pillow]:
   Descàrrega dinàmica de Plus Jakarta Sans, tokenització Markdown i renderitzat
   de la capçalera estil Tweet (Avatar 110px + Nom + Text amb salts de línia precisos).
7. Composició de Vídeo [MoviePy 2.x]:
   Creació del llenç vertical 1080x1920, posicionament relatiu de la capçalera i del
   clip retallat, i exportació H.264/AAC a 30 FPS.
8. Despatxador Dual [Telegram API]:
   - Missatge 1 (sendVideo): Fitxer MP4 renderitzat + resum tècnic (Tweet, Font, ID).
   - Missatge 2 (sendMessage): Caption extens dins d'un bloc <code> llest per copiar.
9. Transició d'Estat i Persistència:
   - Si té èxit: Marca l'estat a 'done' a [sources.csv], desa l'ID a [processed_videos.json]
     i finalitza l'execució (1 vídeo per cicle).
   - Si falla (vídeo privat/esborrat o error d'IA): Marca l'estat a 'failed' a [sources.csv]
     i avança immediatament al següent element 'pending' de la llista.
   - El workflow fa commit i push dels canvis a GitHub amb '[skip ci]'.


-------------------------------------------------------------------------------
2. INGESTA CONTINUA I GESTIÓ DE CUA (Cloudflare Worker + sources.csv)
-------------------------------------------------------------------------------

A. Arquitectura del Webhook Serverless (worker.js):
   - Hostatjat a Cloudflare Workers (execució a l'Edge, cost zero, actiu 24/7).
   - Rep peticions POST de Telegram (setWebhook).
   - Respon SEMPRE amb codi HTTP 200 per evitar que Telegram posi en pausa el webhook.
   - Comanda de diagnòstic: '/id' o '/start' retorna el Chat ID del remitent.
   - Filtratge de Seguretat: Comprova que 'chat.id == TELEGRAM_CHAT_ID' abans de processar.
   - Neteja i deduplicació d'URLs: Extreu el shortcode únic (/reel/SHORTCODE/) i
     comprova si ja existeix dins de sources.csv abans de fer commit.
   - Crida a la GitHub Contents API (PUT /repos/:owner/:repo/contents/sources.csv)
     amb codificació Base64 segura per a caràcters UTF-8.

B. Format del Fitxer sources.csv:
   Format CSV estàndard amb dues columnes:
   ----------------------------------------------------
   reel_url,status
   https://www.instagram.com/reel/C8XYZ123/,done
   https://www.instagram.com/reel/DZh4eZEC5gk/,failed
   https://www.instagram.com/reel/DYCoDpkIKrn/,pending
   ----------------------------------------------------
   Valors d'estat permesos:
   - 'pending': Vídeo a la cua pendent de renderitzar.
   - 'done': Vídeo processat, renderitzat i notificat amb èxit.
   - 'failed': Vídeo amb error irrecuperable (esborrat, privat o fallada persistent d'IA).


-------------------------------------------------------------------------------
3. INGESTIÓ I GESTIÓ DE VÍDEO (yt-dlp)
-------------------------------------------------------------------------------

A. Problemàtica de Frame Rate Variable (VFR):
   Els vídeos de xarxes socials utilitzen freqüentment VFR. Utilitzar índexs de
   fotogrames directes d'OpenCV (CAP_PROP_POS_FRAMES) provoca desplaçaments temporals
   severs i lectures buides.
   REGLE CRÍTICA: Totes les captures de fotogrames s'han de fer SEMPRE per
   temps absolut en mil·lisegons (CAP_PROP_POS_MSEC o clip.get_frame(t)).

B. Mitigació de Bloquejos i Rate-Limiting:
   Suporta injecció de fitxer de galetes Netscape mitjançant la variable
   INSTAGRAM_COOKIES_FILE per evitar errors HTTP 429 des de servidors de GitHub Actions.

C. Idempotència Dual:
   El pipeline garanteix que cap vídeo es repeteixi mitjançant doble comprovació:
   1. Filtre d'estat 'pending' a sources.csv.
   2. Historial persistent d'IDs únics a processed_videos.json.


-------------------------------------------------------------------------------
4. ALGORISME DE VISIÓ PER COMPUTADOR: DETECCIÓ I CROP INTEL·LIGENT (ROI)
-------------------------------------------------------------------------------

A. Objectiu:
   Aïllar el contingut multimèdia dinàmic descartant capçaleres de text estàtiques,
   marcs de memes, fons negres/blancs afegits i barres d'interfície d'usuari.

B. Mètode Implementat (find_video_box_in_frame):
   1. Estimació del Color de Fons (C_bg):
      Mostreja franges de 15 píxels als extrems superior i inferior del fotograma.
      S'aplica np.median per eliminar artefactes de compressió de vídeo.
   2. Màscara de Primer Pla (Foreground Mask):
      diff = max(|Pixel(R,G,B) - C_bg(R,G,B)|) > 30.
   3. Filtre de Text per Seqüència Contínua (Run-Length Spatial Span):
      El text o logotips contenen píxels actius dispersos en blocs petits (<25% d'amplada).
      Un vídeo real ocupa una franja contínua superior al 65% de l'amplada de la pantalla.
      S'escaneja fila a fila calculant la seqüència màxima contínua (get_longest_consecutive_run).
      Les files amb seqüència >= W * 0.65 defineixen y1 i y2.
   4. Escaneig Horitzontal de Columnes (x1, x2):
      Dins de la franja y1:y2, les columnes amb densitat vertical > 65% defineixen x1 i x2.
   5. Consens Multi-Temporal (6 fotogrames):
      Es processen 6 fotogrames al llarg de la línia de temps del clip i es calcula
      la MEDIANA ESTADÍSTICA de les coordenades: (x, y, w, h) = np.median(boxes, axis=0).


-------------------------------------------------------------------------------
5. INTEL·LIGÈNCIA ARTIFICIAL MULTIMODAL I PROMPT ENGINEERING
-------------------------------------------------------------------------------

A. Jerarquia de Models Actius (Failover Queue):
   1. Google Gemini (Principal - google-genai SDK):
      - 'gemini-3.6-flash' (Model recomanat d'alta velocitat i precisió)
      - 'gemini-2.5-flash'
      - 'gemini-2.0-flash'
   2. Groq Cloud (Fallback - groq SDK):
      - 'qwen/qwen3.6-27b' (Visió multimodal)
      - 'meta-llama/llama-4-scout-17b-16e-instruct'

B. Gestió de Saturació i Reintents:
   Si les APIs estan saturades (HTTP 503 / 429), la funció analyze_content_with_retry
   executa fins a 5 intents esperant 60 segons entre cadascun.
   Si després de 5 intents cap servei respon:
   - S'envia una alerta d'error crítica a Telegram (send_telegram_alert).
   - Es marca el vídeo com a 'failed' a sources.csv i s'avança al següent.

C. Regles Estrictes de Prompts:
   1. Detecció d'Autor Original: La IA distingeix entre el compte agregador/curador
      que ha resubit el vídeo (ex: @wealth, @pubity) i la font real
      (ex: 'Media: @creador', marques d'aigua primàries). S'ignora l'agregador.
   2. Format del Tweet: Text en anglès estructurat en 1 o 2 paràgrafs (\n\n).
   3. Negretes Selectives: S'exigeix a la IA que posi asteriscs Markdown
      **a les 2-4 paraules clau del punchline**.
   4. Regla Anti-Tofu: Prohibició estricta d'emojis i símbols matemàtics a
      'tweet_text' per evitar errors de renderitzat tipogràfic (≡).
   5. Neteja per Regex (clean_tweet_text): Filtre en Python que elimina caràcters
      no alfanumèrics o símbols Unicode suplementaris abans de dibuixar amb Pillow.


-------------------------------------------------------------------------------
6. MOTOR TIPOGRÀFIC I RENDERITZAT DE CAPÇALERA (Pillow)
-------------------------------------------------------------------------------

A. Renderitzador Tipogràfic (create_tweet_header_image):
   1. Descàrrega Dinàmica de Fonts (ensure_fonts):
      Descarrega automàticament els fitxers .ttf oficials de Plus Jakarta Sans
      (Regular, SemiBold, Bold) des del repositori oficial a assets/fonts/.
   2. Tokenitzador Markdown de Dues Fases (tokenize_markdown_text):
      Transforma el text amb marcadors ** en una llista de tuples: [(paraula, es_negreta), ...].
   3. Ajust de Línia amb Mètriques Exactes (wrap_tokenized_text):
      Mesura l'amplada exacta de cada paraula utilitzant la font corresponent
      (Bold o Regular) per calcular el salt de línia amb precisió de píxel.
   4. Jerarquia Visual del Llenç:
      - Avatar Circular: 110x110 px (carrega assets/logo.png amb màscara el·líptica).
      - Nom ('Feedity'): 48pt (PlusJakartaSans-SemiBold, Blanc).
      - Username ('@feedity.tv'): 38pt (PlusJakartaSans-Regular, Gris #71767B).
      - Cos del Tweet: 44pt (PlusJakartaSans Regular/Bold, Blanc, interlineat 62px).


-------------------------------------------------------------------------------
7. COMPOSICIÓ DE VÍDEO (MoviePy 2.x)
-------------------------------------------------------------------------------

- Mida del Llenç: 1080 x 1920 píxels (Fons negre sòlid).
- Posicionament Vertical:
  * Capçalera Tweet: Posicionada a y = 180 px.
  * Vídeo retallat (escalat a 1080 px d'amplada): Posicionat a y = 180 + header_height + 10 px.
- Renderitzat d'Exportació:
  * Còdec de vídeo: libx264
  * Còdec d'àudio: aac
  * FPS: 30
  * Preset: fast


-------------------------------------------------------------------------------
8. DESPATXADOR DE NOTIFICACIONS A TELEGRAM
-------------------------------------------------------------------------------

Per superar el límit de caràcters de l'API de Telegram, la notificació s'emet en DOS missatges:

1. Missatge 1 (sendVideo):
   Fitxer MP4 final + resum bàsic (Tweet Text, Font Original, ID del vídeo).

2. Missatge 2 (sendMessage):
   Text complet del caption d'Instagram formatat dins d'un bloc de codi HTML <code>.
   - Permet copiar tot el text amb un sol toc a la pantalla del mòbil.
   - Inclou el disclaimer legal obligatori invariable a l'última línia:
     "All rights belong to the respective owner. DM for credit or removal."


-------------------------------------------------------------------------------
9. VARIABLES D'ENTORN I SECRETS REQUERITS
-------------------------------------------------------------------------------

A. A GitHub Secrets (Actions):
   - TELEGRAM_BOT_TOKEN      : Token del bot de Telegram de @BotFather.
   - TELEGRAM_CHAT_ID        : ID numèric de l'usuari o canal receptor.
   - GEMINI_API_KEY          : Clau d'API de Google AI Studio (Model principal).
   - GROQ_API_KEY            : Clau d'API de Groq Console (Model fallback).
   - INSTAGRAM_COOKIES       : (Opcional) Contingut de cookies.txt per a yt-dlp.

B. A Cloudflare Workers (Settings -> Variables):
   - TELEGRAM_BOT_TOKEN      : Token del bot de Telegram.
   - TELEGRAM_CHAT_ID        : ID numèric de l'usuari autoritzat.
   - GITHUB_REPO             : Nom del repositori en format 'usuari/nom-del-repo'.
   - GITHUB_TOKEN            : Personal Access Token (PAT) de GitHub amb permisos 'repo'.

   i continuar amb el següent 'pending' per garantir la continuïtat del servei.
