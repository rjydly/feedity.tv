===============================================================================
FEEDITY VIDEO PIPELINE — ESPECIFICACIÓ TÈCNICA I ARQUITECTURA DEL SISTEMA
===============================================================================
Fitxer de referència tècnica per a desenvolupadors i models d'IA.
Data de revisió: 2026
Objectiu: Normalització, comprensió visual, redisseny tipogràfic, generació
de portades editorials i publicació multicanal 100% autònoma de vídeos curts
(Instagram Reels / TikTok / Facebook Reels) en format vertical 9:16 (1080x1920 px).

-------------------------------------------------------------------------------
1. VISIÓ GENERAL DEL PIPELINE I FLUX DE DADES
-------------------------------------------------------------------------------

El sistema combina una capa serverless d'ingesta ràpida (Telegram + Cloudflare)
amb un motor d'edició a GitHub Actions i un despatxador multicanal a Buffer:

1. Ingesta Immediata [Telegram -> Cloudflare Worker -> GitHub API]:
   L'usuari comparteix un Reel directament al Bot de Telegram. Un Cloudflare Worker
   serverless valida l'enllaç, comprova el Chat ID autoritzat i afegeix la fila
   'url,pending' directament a [sources.csv] mitjançant l'API REST de GitHub.
2. Cua d'Execució [GitHub Actions / Cron 10 cops al dia]:
   El pipeline llegeix [sources.csv] i selecciona el primer element amb estat 'pending'.
3. Descàrrega de Vídeo [yt-dlp]:
   Descàrrega en format MP4 (amb suport de cookies.txt i gestió de VFR).
4. Visió per Computador [OpenCV + NumPy]:
   Detecció del requadre del vídeo real mitjançant anàlisi de seqüència contínua
   (Run-Length Spatial Span) ignorant fons negres/blancs i text estàtic.
5. Intel·ligència Artificial [Gemini 3.6 Flash -> Groq Fallback]:
   Comprensió de l'escena, OCR del text original, identificació de l'autor primari,
   paràfrasi viral en anglès amb negretes (**bold**), titular editorial (3-6 paraules)
   i redacció del caption amb estricta coherència temàtica anti-al·lucinació.
6. Motor Tipogràfic [Pillow]:
   Descàrrega dinàmica de Plus Jakarta Sans, tokenització Markdown i renderitzat
   de la capçalera estil Tweet (Avatar 110px + Nom + Text amb salts de línia precisos).
7. Disseny de Portada Editorial [Pillow]:
   Llenç 1080x1920 negre sòlid, requadre retallat del vídeo desenfocat (Gaussian Blur)
   al centre, titular gran blanc amb ombra i logotip corporatiu gegant de 190 px
   centrats exactament a la Safe Zone 1:1 (y = 960 px), desat a videos/final_thumbnail.jpg.
8. Composició de Vídeo i Frame 0 [MoviePy 2.x]:
   Composició vertical 1080x1920 (Capçalera Tweet + Vídeo retallat) i incrustació
   de la miniatura com a primer fotograma del clip (Frame 0: 1/30 segons = 33.3 ms),
   desat a videos/video_{id}.mp4.
9. Neteja de Media i Sincronització Prèvia [Git Subprocess]:
   Eliminació de fitxers antics dins de 'videos/', commit i push de la carpeta
   'videos/' amb 'git add -A' a GitHub ABANS de cridar Buffer per evitar desfasaments.
10. Publicació Multicanal [Buffer GraphQL API]:
    Publicació simultània a Instagram Reels, TikTok i Facebook Reels mitjançant
    l'enllaç públic 'raw.githubusercontent.com/.../main/videos/video_{id}.mp4' amb 'thumbnailOffset: 0'.
11. Despatxador de Notificacions [Telegram API]:
    - Si TEST_MODE = True: Enviament complet (Vídeo MP4 + Foto Portada + Caption).
    - Si TEST_MODE = False (Producció): Missatge de text breu de confirmació (sense arxius pesats).
12. Transició d'Estat i Persistència:
    - Si té èxit: Marca 'done' a [sources.csv], desa a [processed_videos.json] i finalitza.
    - Si falla: Marca 'failed' a [sources.csv] i avança immediatament al següent pendent.

2. INGESTA CONTINUA I GESTIÓ DE CUA (Cloudflare Worker + sources.csv)
-------------------------------------------------------------------------------

A. Arquitectura del Webhook Serverless (worker.js):
   - Hostatjat a Cloudflare Workers (execució a l'Edge, cost zero, actiu 24/7).
   - Rep peticions POST de Telegram (setWebhook).
   - Respon SEMPRE amb codi HTTP 200 per evitar que Telegram posi en pausa el webhook.
   - Comanda de diagnòstic: '/id' o '/start' retorna el Chat ID del remitent.
   - Filtratge de Seguretat: Comprova que 'chat.id == TELEGRAM_CHAT_ID' abans de processar.
   - Neteja i deduplicació d'URLs: Extreu el shortcode únic (/reel/SHORTCODE/) i
     comprova si ja existeix dins de sources.csv abans de fer commit.
   - Crida a la GitHub Contents API (PUT /repos/:owner/:repo/contents/sources.csv)
     amb codificació Base64 segura per a caràcters UTF-8.

B. Format del Fitxer sources.csv:
   Format CSV estàndard amb dues columnes:
   ----------------------------------------------------
   reel_url,status
   https://www.instagram.com/reel/C8XYZ123/,done
   https://www.instagram.com/reel/DZh4eZEC5gk/,failed
   https://www.instagram.com/reel/DYCoDpkIKrn/,pending
   ----------------------------------------------------
   Valors d'estat permesos:
   - 'pending': Vídeo a la cua pendent de renderitzar.
   - 'done': Vídeo processat, renderitzat i publicat amb èxit.
   - 'failed': Vídeo amb error irrecuperable (esborrat, privat o fallada d'IA).


-------------------------------------------------------------------------------
3. INGESTIÓ I GESTIÓ DE VÍDEO (yt-dlp)
-------------------------------------------------------------------------------

A. Problemàtica de Frame Rate Variable (VFR):
   Els vídeos de xarxes socials utilitzen freqüentment VFR. Utilitzar índexs de
   fotogrames directes d'OpenCV (CAP_PROP_POS_FRAMES) provoca desplaçaments temporals
   severs i lectures buides.
   REGLE CRÍTICA: Totes les captures de fotogrames s'han de fer SEMPRE per
   temps absolut en mil·lisegons (CAP_PROP_POS_MSEC o clip.get_frame(t)).

B. Mitigació de Bloquejos i Rate-Limiting:
   Suporta injecció de fitxer de galetes Netscape mitjançant la variable
   INSTAGRAM_COOKIES_FILE per evitar errors HTTP 429 des de servidors de GitHub Actions.

C. Idempotència Dual:
   El pipeline garanteix que cap vídeo es repeteixi mitjançant doble comprovació:
   1. Filtre d'estat 'pending' a sources.csv.
   2. Historial persistent d'IDs únics a processed_videos.json.


-------------------------------------------------------------------------------
4. ALGORISME DE VISIÓ PER COMPUTADOR: DETECCIÓ I CROP INTEL·LIGENT (ROI)
-------------------------------------------------------------------------------

A. Objectiu:
   Aïllar el contingut multimèdia dinàmic descartant capçaleres de text estàtiques,
   marcs de memes, fons negres/blancs afegits i barres d'interfície d'usuari.

B. Mètode Implementat (find_video_box_in_frame):
   1. Estimació del Color de Fons (C_bg):
      Mostreja franges de 15 píxels als extrems superior i inferior del fotograma.
      S'aplica np.median per eliminar artefactes de compressió de vídeo.
   2. Màscara de Primer Pla (Foreground Mask):
      diff = max(|Pixel(R,G,B) - C_bg(R,G,B)|) > 30.
   3. Filtre de Text per Seqüència Contínua (Run-Length Spatial Span):
      El text o logotips contenen píxels actius dispersos en blocs petits (<25% d'amplada).
      Un vídeo real ocupa una franja contínua superior al 65% de l'amplada de la pantalla.
      S'escaneja fila a fila calculant la seqüència màxima contínua (get_longest_consecutive_run).
      Les files amb seqüència >= W * 0.65 defineixen y1 i y2.
   4. Escaneig Horitzontal de Columnes (x1, x2):
      Dins de la franja y1:y2, les columnes amb densitat vertical > 65% defineixen x1 i x2.
   5. Consens Multi-Temporal (6 fotogrames):
      Es processen 6 fotogrames al llarg de la línia de temps del clip i es calcula
      la MEDIANA ESTADÍSTICA de les coordenades: (x, y, w, h) = np.median(boxes, axis=0).

5. INTEL·LIGÈNCIA ARTIFICIAL MULTIMODAL I PROMPT ENGINEERING
-------------------------------------------------------------------------------

A. Jerarquia de Models Actius (Failover Queue):
   1. Google Gemini (Principal - google-genai SDK):
      - 'gemini-3.6-flash' (Model recomanat d'alta velocitat i precisió)
      - 'gemini-2.5-flash'
      - 'gemini-2.0-flash'
   2. Groq Cloud (Fallback - groq SDK):
      - 'qwen/qwen3.6-27b' (Visió multimodal)
      - 'meta-llama/llama-4-scout-17b-16e-instruct'

B. Regla d'Or de Coherència Temàtica Anti-Al·lucinació:
   El prompt imposa que 'tweet_text' i 'generated_caption' descriguin estrictament
   el mateix subjecte i to:
   - Si el vídeo és un meme/humor: Tant el tweet com el caption han d'explicar el
     context de comèdia. Queda terminantment prohibit inventar dades científiques inconnexes.
   - Si el vídeo és educatiu/científic: S'explica la troballa real mostrada.

C. Estructura de Resposta JSON de la IA:
   - 'credits': Autor original identificat (o buit).
   - 'tweet_text': Paràfrasi viral en anglès (1-2 paràgrafs, sense emojis, 2-4 paraules en **bold**).
   - 'thumbnail_title': Titular agressiu de 3 a 6 paraules en majúscules.
   - 'generated_caption': Història explicativa + CTA + 8-12 hashtags + crèdits + disclaimer legal.

6. MOTOR TIPOGRÀFIC I CAPÇALERA DE TWEET (Pillow)
-------------------------------------------------------------------------------

A. Renderitzador Tipogràfic (create_tweet_header_image):
   1. Descàrrega Dinàmica de Fonts (ensure_fonts):
      Descarrega automàticament els fitxers .ttf oficials de Plus Jakarta Sans
      (Regular, SemiBold, Bold) des del repositori oficial a assets/fonts/.
   2. Tokenitzador Markdown de Dues Fases (tokenize_markdown_text):
      Transforma el text amb marcadors ** en una llista de tuples: [(paraula, es_negreta), ...].
   3. Ajust de Línia amb Mètriques Exactes (wrap_tokenized_text):
      Mesura l'amplada exacta de cada paraula utilitzant la font corresponent
      (Bold o Regular) per calcular el salt de línia amb precisió de píxel.
   4. Jerarquia Visual del Llenç:
      - Avatar Circular: 110x110 px (carrega assets/logo.png amb màscara el·líptica).
      - Nom ('Feedity'): 48pt (PlusJakartaSans-SemiBold, Blanc).
      - Username ('@feedity.tv'): 38pt (PlusJakartaSans-Regular, Gris #71767B).
      - Cos del Tweet: 44pt (PlusJakartaSans Regular/Bold, Blanc, interlineat 62px).


-------------------------------------------------------------------------------
7. GENERACIÓ DE MINIATURA EDITORIAL I SAFE ZONE 1:1 (Pillow)
-------------------------------------------------------------------------------

A. Arquitectura Visual (create_editorial_thumbnail):
   1. Carpeta de Destí: S'emmagatzema automàticament a 'videos/final_thumbnail.jpg'.
   2. Llenç Base: Fons negre sòlid 1080x1920 px.
   3. Bloc Central de Vídeo: Fotograma extret del vídeo amb crop aplicat, escalat a
      1080 px d'amplada, centrat verticalment i amb desenfocament gaussià intens
      (GaussianBlur radius=32) més un filtre fosc (RGBA 0,0,0,130).
   4. Safe Zone 1:1 d'Instagram: Tot el text i el logotip se situen centrats
      al voltant de l'eix vertical y = 960 px (entre y=420 i y=1500 px).
   5. Titular: Tipografia Plus Jakarta Sans Bold 76pt en blanc amb ombra reforçada.
   6. Logotip Gegant: Cercle de 190 px de diàmetre (carrega assets/logo.png o dibuixa
      cercle groc amb la 'f' blanca) posicionat just a sota del titular amb un gap de 46 px.


-------------------------------------------------------------------------------
8. COMPOSICIÓ DE VÍDEO I EMBEDDING DE FRAME 0 (MoviePy 2.x)
-------------------------------------------------------------------------------

- Mida del Llenç: 1080 x 1920 píxels (Fons negre sòlid).
- Posicionament Vertical del Vídeo:
  * Capçalera Tweet: Posicionada a y = 180 px.
  * Vídeo retallat (1080 px amplada): Posicionat a y = 180 + header_height + 10 px.
- Embedding del Frame 0 (Thumbnail Offset 0 ms):
  * Es genera un clip estàtic de la portada editorial:
    cover_clip = ImageClip(thumbnail_np).with_duration(1.0 / 30.0) # Exactament 33.3 ms
  * S'encadena a l'inici del clip principal:
    final_video = concatenate_videoclips([cover_clip, main_composite_clip])
  * Permet a Buffer, Instagram i TikTok extreure la portada exacta amb 'thumbnailOffset: 0'
    sense que l'espectador percebi cap interrupció visual en prémer Play.
- Exportació: Còdec libx264, àudio aac, 30 FPS, preset fast ('videos/video_{id}.mp4').


-------------------------------------------------------------------------------
9. GESTIÓ D'EMMAGATZEMATGE 'videos/' I PUBLICACIÓ BUFFER
-------------------------------------------------------------------------------

A. Gestió i Neteja de la Carpeta 'videos/':
   - La carpeta 'videos/' es crea automàticament si no existeix (os.makedirs).
   - Neteja prèvia (cleanup_videos_dir): Abans de sincronitzar el nou vídeo, s'esborren
     tots els fitxers antics de 'videos/' deixant únicament el vídeo i miniatura actius.
   - Sincronització Git Prèvia (push_media_to_github):
     S'executa 'git add -A videos/' per registrar tant la pujada del nou fitxer com
     l'eliminació dels obsolets a Git ABANS de cridar l'API de Buffer. Això elimina
     al 100% qualsevol desfasament temporal entre vídeo i caption.

B. Publicació via GraphQL Mutation (publish_to_buffer):
   - Endpoint: https://api.buffer.com
   - URL del Vídeo Públic: https://raw.githubusercontent.com/:repo/main/videos/video_:id.mp4
   - Consulta Unitària de Canal: Identifica el servei de cada ID via 'GetChannel'.
   - Assignació de Metadades per Xarxa:
     * Instagram Reels: metadata: { instagram: { type: "reel", shouldShareToFeed: true } }
     * Facebook Reels: metadata: { facebook: { type: "reel" } }
     * TikTok: Enviament estàndard directe.
   - Reintent Intel·ligent (Fail-Safe): Si la resposta conté 'require a type',
     intercepta l'error i re-envia la mutació injectant el format Reel adequat a l'acte.

10. MODES D'OPERACIÓ (TEST_MODE) I TELEGRAM
-------------------------------------------------------------------------------

El comportament es controla mitjançant la variable booleana TEST_MODE a main.py:

A. Mode de Proves (TEST_MODE = True):
   - NO publica a Buffer.
   - NO desa a processed_videos.json ni canvia l'estat a sources.csv.
   - Envia per Telegram: Vídeo MP4 (sendVideo) + Foto Portada (sendPhoto) + Caption (sendMessage).

B. Mode de Producció (TEST_MODE = False):
   - Publica automàticament a Instagram, TikTok i Facebook via Buffer.
   - Desa l'ID a processed_videos.json i marca 'done' a sources.csv.
   - Envia per Telegram: Únicament un missatge de text breu de confirmació amb l'ID
     i el títol (evitant descarregar arxius pesats al dispositiu mòbil).

12. VARIABLES D'ENTORN I SECRETS REQUERITS
-------------------------------------------------------------------------------

A. A GitHub Secrets (Actions):
   - TELEGRAM_BOT_TOKEN      : Token del bot de Telegram de @BotFather.
   - TELEGRAM_CHAT_ID        : ID numèric de l'usuari receptor.
   - GEMINI_API_KEY          : Clau d'API de Google AI Studio (Model principal).
   - GROQ_API_KEY            : Clau d'API de Groq Console (Model fallback).
   - BUFFER_ACCESS_TOKEN     : Token d'accés de l'API de Buffer.
   - BUFFER_CHANNEL_IDS      : IDs dels canals connectats separats per comes.
   - INSTAGRAM_COOKIES       : (Opcional) Contingut de cookies.txt per a yt-dlp.

B. A Cloudflare Workers (Settings -> Variables):
   - TELEGRAM_BOT_TOKEN      : Token del bot de Telegram.
   - TELEGRAM_CHAT_ID        : ID numèric de l'usuari autoritzat.
   - GITHUB_REPO             : Nom del repositori en format 'usuari/nom-del-repo'.
   - GITHUB_TOKEN            : Personal Access Token (PAT) de GitHub amb permís 'repo'.

13. REGLES INVARIABLES PER A FUTURES MODIFICACIONS
-------------------------------------------------------------------------------

1. Mantingueu sempre CAP_PROP_POS_MSEC a OpenCV per evitar desincronització amb VFR.
2. Mantingueu el renderitzat del Tweet per Pillow (mai MoviePy TextClip).
3. Ordre d'IA: Google Gemini 3.6 Flash com a principal, Groq com a fallback.
4. El Cloudflare Worker ha de retornar SEMPRE HTTP 200 a Telegram.
5. Els arxius de vídeo s'han de desar sempre dins de 'videos/'.
6. La sincronització Git (git add -A videos/ && git push) s'ha d'executar SEMPRE
   ABANS de cridar l'API de Buffer.
7. Si un vídeo falla, s'ha de marcar com a 'failed' a sources.csv i continuar
   immediatament amb el següent 'pending' per no bloquejar el flux.
8. Mantingueu sempre el disclaimer final invariable a format_final_caption.
